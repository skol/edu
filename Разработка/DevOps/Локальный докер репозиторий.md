Для сети из 3–5 машин лучше всего поднять **официальный Docker Registry** на одном из серверов, настроить его на работу по **HTTP** (без SSL, чтобы не возиться с сертификатами в локальной сети) и добавить этот адрес в исключения на всех остальных машинах.

Официальный Docker Registry не имеет встроенного графического интерфейса, и в нем нет автоматической очистки диска. Все операции по просмотру и удалению делаются либо через **API (командами в терминале)**, либо с помощью подключения **стороннего легкого Web UI**.

# Как увидеть содержимое репозитория (без Web UI)

Реестр отдает всю информацию через обычные HTTP-запросы (REST API). Вы можете делать их с помощью утилиты `curl` с любой машины в сети.

## Посмотреть список всех образов:
```bash
curl -X GET https://<registry-domain>/v2/_catalog
```
Если ваш реестр требует авторизации, добавьте заголовок с базовой аутентификацией (Basic Auth):
```bash
curl -u username:password https://<registry-domain>/v2/_catalog
```

## Параметры пагинации

Если образов очень много, ответ может быть длинным. API поддерживает пагинацию с помощью параметров запроса:

- `n` — максимальное количество элементов в выдаче (например, `?n=50`).

- `last` — имя последнего репозитория из предыдущей выдачи, с которого нужно продолжить следующий запрос (например, `?n=50&last=imagename`).

Пример запроса с пагинацией:
```bash
curl "https://<registry-domain>/v2/_catalog?n=10&last=my-image"
```

## Полезные детали

- **Список тегов:** Чтобы посмотреть список тегов для конкретного найденного образа, используйте другой официальный метод API: `GET /v2/<name>/tags/list`.

- **Ограничения:** Официальный Docker Hub (`registry-1.docker.io`) отключает или ограничивает доступ к публичному каталогу `/_catalog` в целях безопасности, поэтому этот метод в основном применяется для приватных локальных инстансов Docker Registry.

# Как «прибраться» и удалить лишнее

Удаление в Docker Registry состоит из двух шагов: сначала вы удаляете ссылку на образ через API (удаление манифеста), а затем запускаете встроенный сборщик мусора, чтобы физически стереть файлы с диска.

## Шаг 1: Разрешаем удаление в настройках

По умолчанию удаление через API заблокировано. Чтобы его включить, нужно передать контейнеру переменную окружения `REGISTRY_STORAGE_DELETE_ENABLED=true`.

Перезапустите контейнер реестра на сервере с этой опцией:
```bash
docker stop local-registry
docker rm local-registry

docker run -d \
  -p 5000:5000 \
  --restart=always \
  --name local-registry \
  -e REGISTRY_STORAGE_DELETE_ENABLED=true \
  -v /opt/registry:/var/lib/registry \
  registry:2
```

## Шаг 2: Удаление конкретного тега (образа)

Чтобы удалить образ, нужно узнать его уникальный идентификатор (**Docker-Content-Digest**).

1. Запросите манифест образа, обязательно добавив специальный заголовок в `curl`:
	```bash
	curl -sI -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
	https://<registry_host>/v2/<repo_name>/manifests/<tag_name>
	```
2. В ответе найдите строчку, начинающуюся с `Docker-Content-Digest:`. Она выглядит примерно так:  
    `Docker-Content-Digest: sha256:701108b566a530...`
    
3. Отправьте запрос на удаление (`DELETE`), используя этот длинный хэш `sha256:...`:
	```bash
	curl -X DELETE \
	  https://<registry_host>/v2/<repo_name>/manifests/sha256:<digest_hash>
	```
	_После этого образ пропадет из списков, но место на диске еще не освободится._

## Шаг 3: Очистка диска (Сборка мусора / Garbage Collection)

Docker Registry не удаляет файлы сразу, чтобы не заблокировать текущие скачивания. Чтобы физически вернуть место на жестком диске, выполните команду внутри контейнера реестра:
```bash
docker exec local-registry bin/registry garbage-collect /etc/docker/registry/config.yml
```
*Эту команду можно добавить в cron на сервере (например, раз в неделю), чтобы очистка происходила автоматически.*

# Альтернатива: Легкий Web UI (Рекомендуется)

Если не хочется возиться с `curl` и хэшами, можно рядом с реестром поднять очень легкий веб-интерфейс, например **Docker Registry UI**

(от joxit). Он весит всего около 15 МБ, работает в браузере и позволяет в один клик смотреть образы и нажимать кнопку «Удалить».

Для этого на сервере запустите UI-контейнер:
```bash
docker run -d \
  -p 8080:80 \
  --name registry-ui \
  --restart=always \
  -e REGISTRY_URL=http://192.168.1.100:5000 \
  -e DELETE_IMAGES=true \
  joxit/docker-registry-ui:latest
```
Теперь вы сможете открыть в браузере адрес `http://192.168.1.100:8080` и управлять репозиторием мышкой.  
_(Обратите внимание: после удаления образов через Web UI запускать сборщик мусора `garbage-collect` из Шага 3 все равно нужно, чтобы очистить диск)._

# Запуск из docker-compose.yml
```yaml
version: '3.8'

services:
  # 1. Сам Docker Реестр
  registry:
    image: registry:2
    container_name: local-registry
    ports:
      - "5000:5000"
    restart: always
    environment:
      REGISTRY_STORAGE_DELETE_ENABLED: "true" # Разрешаем удаление образов
    volumes:
      - ./data:/var/lib/registry

  # 2. Веб-интерфейс (доступен по порту 8080)
  registry-ui:
    image: joxit/docker-registry-ui:latest
    container_name: local-registry-ui
    ports:
      - "8080:80"
    restart: always
    environment:
      - REGISTRY_URL=http://registry:5000 # Ссылка на контейнер реестра внутри сети Docker
      - DELETE_IMAGES=true                # Включаем кнопку удаления в браузере
    depends_on:
      - registry

  # 3. Автоматический сборщик мусора (очистка диска)
  registry-gc:
    image: registry:2
    container_name: local-registry-gc
    restart: always
    entrypoint: >
      sh -c "while true; do
        echo 'Starting garbage collection...';
        bin/registry garbage-collect /etc/docker/registry/config.yml;
        echo 'Garbage collection finished. Sleeping for 24 hours...';
        sleep 86400;
      done"
    volumes:
      - ./data:/var/lib/registry
    depends_on:
      - registry
```

# Настройка авторизации по паролю (Basic Auth)
## Шаг 1: Создаем файл паролей

Прямо на сервере выполните команду (замените `myuser` на ваше имя пользователя):
```bash
mkdir auth
docker run --entrypoint htpasswd httpd:2.4 -Bbn myuser mypassword > auth/htpasswd
```
*Эта команда создаст папку `auth` и запишет туда зашифрованный пароль `mypassword`.*

## Шаг 2: Обновленный `docker-compose.yml`

Теперь передадим этот файл в контейнеры. Нам нужно обновить настройки самого реестра и передать логин/пароль в Web UI, чтобы он мог авторизоваться в реестре.
```yaml
version: '3.8'

services:
  registry:
    image: registry:2
    container_name: local-registry
    ports:
      - "5000:5000"
    restart: always
    environment:
      REGISTRY_STORAGE_DELETE_ENABLED: "true"
      # Включаем авторизацию:
      REGISTRY_AUTH: "htpasswd"
      REGISTRY_AUTH_HTPASSWD_REALM: "Registry Realm"
      REGISTRY_AUTH_HTPASSWD_PATH: "/auth/htpasswd"
    volumes:
      - ./data:/var/lib/registry
      - ./auth:/auth:ro # Пробрасываем папку с паролем

  registry-ui:
    image: joxit/docker-registry-ui:latest
    container_name: local-registry-ui
    ports:
      - "8080:80"
    restart: always
    environment:
      - REGISTRY_URL=http://registry:5000
      - DELETE_IMAGES=true
      # Указываем UI, какие логин и пароль использовать для подключения к реестру:
      - REGISTRY_USER=myuser
      - REGISTRY_PASSWORD=mypassword
    depends_on:
      - registry

  registry-gc:
    image: registry:2
    container_name: local-registry-gc
    restart: always
    entrypoint: >
      sh -c "while true; do
        echo 'Starting garbage collection...';
        bin/registry garbage-collect /etc/docker/registry/config.yml;
        echo 'Garbage collection finished. Sleeping for 24 hours...';
        sleep 86400;
      done"
    volumes:
      - ./data:/var/lib/registry
    depends_on:
      - registry
```

## Шаг 3: Как теперь логиниться с машин?

Перед тем как делать `push` или `pull`, на каждой из 3–5 машин нужно будет один раз выполнить команду авторизации:
```bash
docker login 192.168.1.100:5000
```
Docker спросит логин и пароль (`myuser` / `mypassword`), сохранит их в систему и больше спрашивать не будет. Web UI (на порту 8080) также запросит этот пароль при входе в браузер.

Детали API смотри здесь: [OCI Distribution Specification](https://github.com/opencontainers/distribution-spec)
